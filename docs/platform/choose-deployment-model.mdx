# Choose a Deployment Model

Onam Cloud offers three deployment models. The right choice depends on who owns the hardware, how isolated the environment needs to be, and where workloads must run.

| Model | Infrastructure | Typical fit |
| --- | --- | --- |
| [OnPublic](../solutions/onpublic.mdx) | Shared sovereign public cloud | Cloud-native workloads, applications, and development environments |
| [OnPrivate](../solutions/onprivate.mdx) | Dedicated, single-tenant environment in an Onam Cloud data centre | Regulated workloads and enterprise platforms |
| [OnBYOPC](../solutions/onbypc.mdx) | Customer-owned infrastructure in the customer's data centre | Existing hardware, local deployment, or maximum infrastructure control |

## Questions to discuss

1. Which jurisdictions and data-residency requirements apply to the workload?
2. Does the workload require shared infrastructure, dedicated tenancy, or customer-owned hardware?
3. Which team owns facilities, hardware, platform operations, and application operations?
4. What capacity, availability, connectivity, and recovery targets are required?

Some environments can combine deployment models. Validate the design, service availability, and operating responsibilities with Onam Cloud before committing workloads.
